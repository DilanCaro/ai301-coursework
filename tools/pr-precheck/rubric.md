# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan-faithful diff | Read the candidate PR's unified diff and commit list against the plan-context block's in-scope / not-in-scope commitments, named files or areas, and any recorded deviation notes. In live mode, compare `git diff main...HEAD` (or the repo's default branch) to `plan.md` including its deviations section. | Pass when every material behavior change in the diff falls inside the plan's stated boundary or a recorded deviation note that re-ties the mismatch, and when every planned deliverable that the plan still claims is present in the diff or honestly deferred in a deviation note that the description also surfaces. An honest disclosed shortfall (deferred work named in the plan and restated in the description) passes. Fail when the diff silently does more than the plan (extra features, config flags, rewrites, unrelated files) or less than the plan still claims, with no deviation note. | required |
| Description matches diff | Read the PR title and description's fidelity claims (what changed, what was deferred, "exactly as planned", "no changes beyond…") against the unified diff and against the plan-context scope. | Pass when the description promises only what the diff contains and does not claim fidelity the diff contradicts. Fail when the description claims the plan was followed exactly while the diff drifted, claims a deliverable the diff omits, or understates material extra work present in the diff. | required |
| Decisive test evidence | Read the candidate PR's test-evidence section against the plan's test plan and the plan-context repro evidence; also note whether the repo's own checks or suite outcome is shown. In live mode, read `test_evidence.md` (or equivalent captured output) the same way. | Pass when the evidence shows an observable before/after (or equivalent decisive artifact) for the plan's named repro or decisive cases through the changed path, and shows the outcome of the repo's own relevant checks or an honest note that names which check failed and why. Fail when evidence is only "tests pass" / "works on my machine", exercises an unchanged control path instead of the failing case, omits a plan-named decisive case with no honest deferral, or never shows the repo's checks. | required |
| Reviewable diff | Read the unified diff and the commit list for debris and unrelated hunks: debug prints, commented-out experiments, dead helpers, TODO litter, pure formatting or import churn, and drive-by edits outside the planned change. | Pass when the fix is visible and reviewable: no debris or unrelated hunks bury the change, and commits do not advertise WIP/debug cleanup as the substance. Fail when debug leftovers, dead code, commented-out blocks, formatting churn, or unrelated edits ride along in a way that obscures the planned change. | required |
| Template and disclosure | Read the PR description against the repo-facts block's PR-template asks, contribution instructions, and stated AI-use policy (and any explicit maintainer template direction in the thread). In live mode, read the repo's `.github/PULL_REQUEST_TEMPLATE.md` and contribution/AI policy the same way. | Pass when every required template section the repo asks for is filled with real content (not left blank or boilerplate-ignored), and when any stated AI-disclosure requirement is met in the author's own words. If the repo states no AI policy and no applicable template ask, those absences are not failures. Fail when a required checklist item, closes/fixes line, changelog/whatsnew ask, or required AI disclosure is visibly unmet. | required |

## Verdict rule

Accept only when every required check passes. Reject when any required
check fails or is unclear. Preferred checks (if any are added later)
appear in the output but never change the verdict. Treat `unclear` on
a required check as fail: missing evidence needed to verify readiness
is a hold.
